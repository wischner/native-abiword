Resource integration and document selection painting were tested on SDL2,
X11 and GEM/gemd. These counts include all 17 icon pairs, Native highlight
checks, and selected-document pixels at three zoom levels. Windows
was cross-built with a pack generated by Linux SDL2's `rc`; its executable
was not run. That SDK build emitted warnings in Native's resource manifest
reader and Windows settings-sidebar code; no Fyodor warnings were reported.
The Windows result predates the document selection change. Other backend
results above predate resource integration.

The GEM combo fix also passes Native's real Rasta/AES input regression and
runtime checks on both direct GEM and gemd. Those tests cover toolbar font/size
popup selection over a canvas and outside-click dismissal. Fyodor's expanded
suite includes style, font, size, color and zoom callback checks;
SDL2 and X11 also include these callback checks; other backends predate them.

Status-bar sizing/placement and disabled history icons pass the current
SDL2, X11 and GEM/gemd desktop suites. GEM uses the document-canvas host;
SDL2 and X11 retain the outer footer. Native's shared status geometry test
also passes on GEM/gemd and SDL2 with visible/hidden scrollbars and resizing.
Other backend results predate these Native API additions.

The follow-up Gemscape/Ted comparison corrects GEM's theme height from 22
to 20 pixels. A portable `set_scroll_content` call then replaces its painted
canvas bars with genuine AES frame scrollbars, eliminating duplicate track
reservation and the bottom gap. No toolkit checks remain in Fyodor's UI code.
The GEM F5 Debug executable at that stage passed 420 checks; Native's real Rasta
scrollbar input and existing status geometry regressions pass. SDL2 and X11
pass their existing suites with the same application source and API. A live
framebuffer confirms native scrollbar sizing and the flush status boundary.

The final toolbar revision passes 819/819 desktop checks on GEM/gemd Debug
using the normal Git-managed Native dependency at `4e6f805` and the latest
GEMIX Docker image. Both rows are 20 pixels high, all command buttons are
20×20, group separators occupy one button width, and fields are 18 pixels high.
Direct GEM also passes 819/819 checks. SDL2's last 668/668 run covers the joined
fields but predates the final separator changes. See [GEM UI audit](GEM-UI.md)
for image provenance, shared icon sources and validation scope.

Under GDB/MI and Xvfb, closing Fyodor's own window exits normally. Closing
the outer Rasta viewer terminates its private debug session and leaves no
session processes behind. Command exit status is preserved. These lifecycle
checks exercise the session wrapper and real mouse input separately from the
portable desktop callback suite.

## Known limits

- **GEM** types ASCII only, because its key packets carry nothing more.
- **GEM performance:** the desktop test now measures typing with painting.
  See [repaint findings](NATIVE-CHANGES.md#gem-typing-and-repaint-cost), including
  the substantial extra cost of the unoptimized, sanitized F5 Debug build.
- **Haiku:** the two failing checks are the paint check. `hotel` captured a solid
  black screen over SSH, so the display was not rendering in that session.
  Compare by running `Haiku, VM` from the desktop.
- **Windows, Wayland, elementary, macOS:** text routing is written, and all but
  macOS compile, but none has been run. macOS code has not been compiled.

The end-to-end runs used a throwaway XTest probe, which is not in the repository.
`tests/ui/test_desktop.cpp` remains the portable suite and enters above the
backend, so see [TESTING.md](TESTING.md) for what it cannot show.
